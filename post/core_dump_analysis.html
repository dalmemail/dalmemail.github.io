Core dump

A core dump is a snapshot of a program memory at a given time, usually written to a plain-text file. They're generated whenever a program triggers a fatal error (such as a segmentation fault).

Core dumps can be used to assist debugging by looking at their raw content, or -better- by loading them into GDB. For this we need the binary file of the program that generated the code dump, compiled with debugging symptoms.

$ gdb path/to/binary path/to/core/dump

Using the backtrace (bt) command we can get a stack trace from the time of the crash. Using the (frame number) command we can switch GDB to the frame number 'number' and evaluate the value of different variables there (using print name_of_variable).

Obtaining core dumps on Linux (systemd)

On systemd core dumps are stored at /var/lib/systemd/coredump, only if the package systemd-coredump (debian/ubuntu) is installed on the system. Then it's possible to list existing coredumps with the $ coredumpctl command. By default core dumps are compressed with zstd (.zst format). It's necessary to decompress them before passing the dump to GDB. Just run:

$ unzstd path/to/file
